## 2. Real bugs (verified, with locations)

### B1 — The Guide can never be assigned housing (HIGH — visible in normal play)
- `updateTownArrivals` (js/main.js:1228) has no `E.GUIDE` condition, so the Guide never enters `townArrivals`.
- `assignNpcHousing` (main.js:1311) and the housing panel (main.js:1366) both key off `townArrivals` → the Guide is never listed in the housing UI.
- Worldgen only sets a spawn *marker* (`w.guidePos`, js/world.js:2274) — no house is built for him.
- Player exploit exists: build walls/floor around wherever the Guide happens to be standing, and he's "housed" by position — but he can never be assigned/moved through the normal system, and he always respawns at `guidePos` (main.js:946, 3351).
- **Fix:** add the Guide to `townArrivals` (housing system already supports him) and/or give worldgen a starter house at `guidePos`.

### B2 — Water is fully static; no liquid physics (MEDIUM — vanilla parity gap)
- 900 consecutive sim-frames: **0 flow changes** in any water tile. Water never drains, flows into holes, settles, or spreads.
- The Acorn tooltip says *"Plant it on grass to grow a tree."* but planting is not implemented (consumed=false, no resulting tree tiles in any probe).
- No bucket/water-use code exists in player.js. **Fix:** liquid settling pass + acorn planting + water/lava buckets.

### B3 — Zombie & Skeleton loot tables are overwritten by duplicate object keys (MEDIUM — silent data loss)
- `B83_ENEMY_DROPS['Zombie']` is assigned the huge ~60-item 1% weapon pool at js/entities.js:508, then **overwritten** at :531 by `{ZOMBIE_ARM, rate:0.02}`.
- `B83_ENEMY_DROPS['Skeleton']` gets the big pool at :509, then is **overwritten** at :525 by `{BONE_SWORD, rate:0.01}`.
- Net effect: the two most common night enemies drop only a single rare item each, and the biggest rare-loot pools in the game are only reachable from Cave Bat / Slime / Angry Bones / etc. buckets.
- **Fix (one line each):** merge the small drop into the big arrays instead of re-assigning the key.

### B4 — Tutorial tip tokens reference items that don't exist (LOW but permanent UX wart)
- js/main.js:5235 `has(I.WORKBENCH)` — token never defined (the base workbench has *no item token at all*; crafting.js:25 uses `special:'workbench'`). So the "Craft a Workbench" tip **never suppresses** once you have wood.
- js/main.js:5238 `I.COPPERTORCH` — undefined; check degenerates to plain `I.TORCH` (torch tip never shows).
- js/main.js:5241 `I.COPPERARMOR / I.IRONARMOR / I.TINARMOR` — all three undefined (hurrah for `hasAny(...)` = always false), so the "Smelt ore → craft armor" tip **shows forever**, even in armor.
- **Fix:** reference the real tokens (`I.GEL + wood → torch` path and the first-piece-of-armor condition can just check equipped armor/slots for `COPPERHELM`-family ids).

### B5 — No armor set bonuses (MEDIUM — vanilla parity gap)
- Defense stacking works exactly (copper 7, cobalt 17 — verified), but there is **no set-bonus logic anywhere** in the runtime. Only the Meteor Helmet description mentions a bonus (js/items.js:5936). Set bonuses are core Terraria progression identity.

## 5. Harness artifacts encountered (for anyone re-running these probes)

These are probe-side issues that were **fixed in the probe scripts, not in the game**:

1. Non-auto weapons need a per-frame MOUSE press: `MOUSE.down = true; step(1/60); MOUSE.down = false;`.
2. `MOUSE.wx/wy` persist until a real mousemove; only `mousemove` recomputes them, so direct assignment is valid aiming.
3. `__resetPlayer` (hp/position/invuln) does not move the player — order matters; set position after.
4. Meteorite `TILE_HARD` values are `[minHits, hardness]` arrays.
5. Inventory has 50 slots; `addStack` silently returns 0 when full — clear inventory between long stages (King Slime's spawn-a-slime loop fills 50 slots in 20k frames).
6. Leftover `p.attackCd`/`p.swingT` from the previous stage silently blocks `tryConsume`/`tryMelee` — zero them first.
7. Pickups auto-vacuum into inventory; drop counts must sum `game.pickups` **and** `p.inventory.slots`.
8. Fishing: each cast consumes 1 worm and each catch adds 1 item, so a flat inventory-total delta reads 0 — measure per-id positive deltas.
9. This game's coin tiers are Silver/Gold/Platinum — there is **no copper coin**; granting `I.COPPERCOIN` is a silent no-op.
10. King Slime hops away on custom physics; a pinned player can't reach it — the probe uses a documented **chase assist** (park next to the boss each sim-second; no scripted damage) to emulate a real player's locomotion.
